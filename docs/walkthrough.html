Design decisions

Each decision with its rationale and where it is implemented.

Access control

Least-privilege IAM

GetObject on 3 names only: hr.csv, app.csv, config.json. PutObject on 2: review.csv, summary.json. No delete.

Why It handles HR data. A bug can't read other paths or wipe a run.

aws/template.yaml · Policies

Access control

ListBucket, only on runs/*

Without it, S3 answers a missing key with 403. With it, 404 NoSuchKey, which the store turns into null.

Why Tell "waiting for the second file" apart from "access denied".

template.yaml · ListBucketSoMissingFilesReturn404 · handler.js s3Store().get

Infrastructure

Bucket name from !Sub

leaver-check-${AWS::AccountId}-${AWS::Region}. The function policy uses that string, not !Ref to the bucket.

Why No circular dependency between bucket, its notification and the function role.

template.yaml · RunsBucket.BucketName

Reliability

Recursion guard

Notifications filter on prefix runs/ and suffix hr.csv or app.csv. runFolder() ignores every other key.

Why Writing results can't start another run. Two layers, one in AWS and one in code.

template.yaml · Events · handler.js runFolder()

Reliability

Failures don't disappear

A failed run is retried twice, then its S3 event and the error go to an SQS queue kept 14 days. A CloudWatch alarm fires on any function error, with optional email through AlarmEmail.

Why S3 invokes the function asynchronously. Without a destination, a failed run is dropped and nobody notices the missing review sheet.

template.yaml · EventInvokeConfig, FailedRunsQueue, ErrorsAlarm

Data handling

Data protection

  • Public access blocked (all four settings)
  • Ownership: BucketOwnerEnforced (no ACLs)
  • SSE-S3 encryption (AES256)
  • Bucket policy denies any request without HTTPS
  • runs/ expires after RetentionDays (default 30)
  • Log group keeps 30 days; logs hold counts only, never names or emails

Why The bucket holds employee names and emails. Keep it private, encrypted and short-lived.

template.yaml · RunsBucket, RunsBucketPolicy, LeaverCheckLogs · handler.js log.info

Infrastructure

Runtime: nodejs24.x on arm64

cfn-lint flagged nodejs20.x as deprecated, so it moved to 24. 512 MB, 60 s timeout.

Why CI lints the template, so the deprecation showed up before any deploy.

template.yaml · Runtime, Architectures

Testing

Testable without AWS

createHandler({ store, log }) takes the storage. Tests pass an in-memory store. One test checks Lambda findings deep-equal the CLI's reconcile().

Why Runs in CI with no AWS account, and proves one engine behind every front end.

Known gaps before production use on AWS

PriorityGapSuggested fix
High

Never deployed

The S3 trigger, S3's permission to invoke the function, the failure queue, the 404-instead-of-403 behavior and nodejs24.x in a given region are only proven by a real deploy.

Deploy to a test account and run the example files end to end.

Medium

One stack per account and region

The bucket name is built from account and region, so a second deploy there fails because the name is taken.

Add the stack name or a parameter to the bucket name.

Medium

No access for other people

The template doesn't grant anyone upload or download rights. The deployer's own admin access works.

Add a role or policy for HR and app owners, limited to runs/.

Low

Untested at scale

Both files are read into memory, with 512 MB and a 60-second limit. Nobody has tried a large export.

Test with a large export and raise memory or timeout if needed.

Low

Package includes the whole repo

CodeUri: ../ bundles the web page, tests and examples too (about 164 KB).

Package only aws/ and the shared script.

Common questions

Isn't s3:ListBucket more access than the function needs?

It's limited to the runs/* prefix. Without it, S3 returns 403 for a missing key, so the function couldn't tell "second file not uploaded yet" from a real permission failure. With it, a missing file is a 404 and the run returns status: "waiting".

Does the Lambda give the same answer as the browser page and CLI?

Yes. It imports the same reconcile() from skill/leaver-check/scripts/leaver-check.js, and a test runs both on the example files and checks the findings and summary are identical.

Do names or emails end up in the logs?

No. The function logs counts only, such as the number of leavers and orphan accounts. Names and emails stay in the bucket, and a test checks the log output.
